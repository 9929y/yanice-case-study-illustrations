# Yanice Case Study Illustrations

Create original editorial illustrations that make the central design insight or product change in a portfolio case study easier to understand. Support wide narrative images, project-card artwork, explicit process maps, system details, before/after changes, user-state sequences, and handoff or journey illustrations. Use context-specific human figures rather than a fixed mascot.

## Style precedence

- Follow the user's request and the image's real page placement for content, language, crop, and format.
- Use Mesh Gradient Art for the visual identity: semantic mesh field, irregular ivory carrier, controlled palette, bold near-black hand-drawn ink, and restrained mesh-tinted accents.
- Use Xiaohei for story selection and composition logic: identify the key action, choose a fitting structure, make a person participate, and keep process direction legible. Do not import its fixed Xiaohei character, white-only background, thin-line palette, Chinese annotation convention, or blanket rejection of formal flowcharts.
- When sources appear to conflict, preserve the priorities above: mesh determines the look; Xiaohei informs how the story is organized; this portfolio's image purpose determines which composition mode applies.

Use the supplied repositories as style and workflow references only. Do not reproduce their exact illustrations, characters, or layouts.

## Workflow

1. **Find the story.** Read the supplied case study or the relevant page on `yaniceyang.com`. Identify the audience, user problem, key insight, design intervention, and outcome. Select one visual anchor per image. Keep project facts faithful to the source; never invent research findings, metrics, quotes, product behavior, or outcomes. If the page is unavailable and the image depends on case-specific details, ask for the relevant excerpt or brief.
2. **Choose the image's job.** Use narrative/insight mode for one case-study turning point; process mode for an explicit workflow, system sequence, handoff, or user journey; card mode for thumbnail recognition; and before/after or user-state mode when change over time is the point. Do not turn a requested process map into a vague metaphor or force every image into a diagram.
3. **Set a visual lock for a set.** Before creating multiple assets for one case study, establish the shared mesh colors and their meanings, background/carrier treatment, ink quality, person-drawing grammar, and any crop constraints. Keep these choices consistent across the set; vary the scene and dominant semantic color only when the story calls for it. Keep an individual person consistent across stages when the sequence depicts the same person, while allowing different projects and roles to have different people.
4. **Choose the composition and shape.** For process mode, preserve source-supported inputs, stages, decisions, handoffs, outputs, and feedback; show order and branching clearly. Use Xiaohei's workflow logic—source → active processing → result—with sparse supporting nodes and distinct routes, adapted to the case. For other modes, reduce the insight to one concrete relationship or action. Match the actual page crop when known; otherwise use 16:9 for wide case-study images and the portfolio card's observed crop, or 4:3 landscape when unknown.
5. **Choose the output format and prompt.** Raster is the default for finished images. For a requested SVG, editable vector, or reusable layered asset, read `references/vector-output.md` and construct native SVG instead of asking the image model for editable vector output. Always use `references/visual-system.md`; also read `references/process-flow.md` for process mode. Give the mesh colors a semantic role tied to the story and keep every form readable at its intended display size.
6. **Generate and inspect.** Generate each requested asset separately. Check the image against the selected mode and quality criteria; revise when the core action, sequence, person, or focal point is unclear, or when the result looks like a generic SaaS poster, decorative gradient, stock vector, or slide graphic.
7. **Deliver clearly.** Save final assets in the active project when one exists, using a dedicated case-study illustration folder and descriptive filenames. Report each asset's role, format, aspect ratio, semantic color role, and saved path. For planning-only requests, return a concise shot list with placement, story anchor, composition mode, visual lock, and aspect ratio instead of generating images.

## People and language

- Draw different people to suit the context of each case study; do not create or repeat a mascot/IP character. Make the depicted person an active participant in the core action, not a decorative bystander.
- Keep people editorial and simplified, with natural gestures and varied silhouettes. Avoid infantilized, chibi, or overly cute character design.
- Prefer no text inside the image. If words are needed, use short English labels grounded in the case study; translate faithfully when the source is not English. Never include Chinese characters, pseudo-text, invented facts, or extra title copy. For exact spelling, use a text overlay when image generation is unreliable.
- Preserve the distinction between an explanatory illustration and actual product evidence. Do not invent interface screens, logos, or data. Use product UI only when it is supplied and genuinely necessary to the story.

## Reference routing

- Read `references/visual-system.md` before generating illustrations. It defines the shared style and guidance for wide narrative and project-card use.
- For an explicit workflow, process diagram, system sequence, onboarding journey, or handoff map, read `references/process-flow.md` and preserve process logic visibly in the composition.
- For a requested editable or layered SVG, read `references/vector-output.md`; keep the same visual lock and use native editable SVG groups.
- When multiple case studies are requested, give each image a distinct metaphor grounded in that project's actual story while keeping palette, line character, and figure treatment coherent across the set.
